# FContex Admin 架构设计

> 前置阅读：[01.项目介绍.md](01.项目介绍.md)。本文档描述目标架构，与现状不一致处以"【现状】"标注。

## 一、架构总览

系统由四层组成，自外向内：

```
┌─────────────────────────────────────────────┐
│  模块层    content / message / ...           │  业务功能，装卸自由
├─────────────────────────────────────────────┤
│  内核层    system（运行库+桌面） + member     │  不可拆卸
├─────────────────────────────────────────────┤
│  引导层    module/startup.php                │  常量、session、内核对象
├─────────────────────────────────────────────┤
│  存储层    store/（config / cache / upload） │  运行时读写
└─────────────────────────────────────────────┘
```

核心原则：

1. **内核不含业务**：任何业务概念（内容类型、前台主题、业务对象）不得进入引导层和内核。
2. **模块是唯一扩展机制**：模块拥有自己的数据表、权限、菜单和生命周期；不存在第二套扩展体系。
3. **约定优于配置**：目录名即模块名，类名、URL、权限名均由命名约定推导，无需注册文件。
4. **依赖单向**：依赖只能指向更早、更基础、更必然存在的一方。内核不依赖任何业务模块，但业务模块可直接使用内核的公共设施（脚本、组件、皮肤、鉴权）；模块之间，后来者可以依赖先有者（如 message 为 content 的条目提供评论服务），反向禁止。

## 二、请求生命周期

```
HTTP 请求
  │
  ▼
index.php ── include ──▶ module/startup.php
                          │  定义路径常量、开启 session
                          │  创建内核对象 $A $U $D $T $R
                          ▼
                        $R->dispatch()
                          │  解析 QUERY_STRING → module / action / params
                          ▼
                ┌─────────────────────────┐
                │ 模块存在？               │
                │  ├ 否 → 404             │
                │  └ 是 → include         │
                │      module/<m>/index.php   （页面渲染）
                ▼
                输出缓冲 → 写入页面缓存（可选） → echo
```

页面内发起的数据操作走独立的动作通道：

```
浏览器 JS ── POST ──▶ module/<m>/control/index.php?mode=fc.<实体>.<动词>
                        │  switch(mode)
                        │  1. $U->checkRights() 权限校验
                        │  2. 参数校验
                        │  3. $D 读写数据
                        │  4. $A->logInsert() 记日志
                        ▼
                     echo 'YES' 或 'ERR|消息|字段名'
```

页面与动作分离是全系统统一约定：页面入口负责渲染，动作接口负责读写，动作接口永远先校验权限再碰数据。

## 三、引导层（module/startup.php）

职责清单：

- 定义系统常量：`SYSTEM_NAME`、`SYSTEM_VERSION`、`SYSTEM_MODULE`（必装模块清单）
- 定义路径常量：`PATH_ROOT` / `PATH_STORE` / `PATH_CONFIG` / `PATH_CACHE` / `PATH_MODULES`
- 定义 URL 常量：`URL_SITE` / `URL_MODULE` 等；内核公共资源 `URL_SCRIPTS` / `URL_TOOLS` / `URL_SKIN`（所有模块可直接使用）
- 开启 session、设置字符集与时区
- 创建内核全局对象 `$A $U $D $T $R`
- 调用内核守卫方法（实现均在 `cls.application.php`）：
  - `$A->csrfInit()` / `$A->csrfCheck()`：CSRF 令牌下发与后台 AJAX 写请求校验（免校验接口清单在类内维护）
  - `FCApplication::requireDatabase()`：数据库配置就绪检查，缺失时非安装请求跳转安装向导
  - `FCApplication::assetVersion()`：静态资源版本号，取内核脚本与各皮肤样式的 mtime

【现状】引导层业务残留清理进度：

| 残留 | 处理 |
|------|------|
| `$C = FCApplication::sharedContent()` | ✅ 已移出：sharedContent() 一并删除，调用方自行 `FCApplication::loadLibrary('content')`，system 对 content 零依赖 |
| `CONTENT_PAGE` ~ `CONTENT_VIDEO` 常量 | ✅ 已移入 cls.content.php |
| 主题常量（`PATH_THEME` 等 6 个） | ✅ 已移入 cls.content.php（随主题归属 content 模块） |
| `PATH_SCRIPTS` / `PATH_TOOLS` 硬指向 system 内部 | ✅ 规则已符合：system 是内核，其 `scripts/`（公共脚本）、`tools/`（公共组件）、`skins/`（后台皮肤）即内核公共资源区，所有模块可直接使用；模块私有资源放自身 `scripts/`、`icons/` |

## 四、内核

### 4.1 应用核心（`$A`，cls.application.php）

- 单例入口 `FCApplication::sharedApplication()`，其余内核对象均由它派生（`sharedMember()` / `sharedDataBase()` / `sharedTemplate()` / `sharedRouter()`）。
- 配置加载 `loadConfig('system.settings')`：从 `store/config/` 读取 PHP 数组配置并缓存。
- 请求安全封装 `strGet()` / `strPost()`：统一入口取参并过滤。
- 编解码 `strEnCode()` / `strDeCode()`；字符串截取 `strLeft()`；缩略图 `getThumb()`。
- 操作日志 `logInsert()`：所有后台写动作的日志统一入口。

### 4.2 路由（`$R`，cls.router.php）

**解析规则**：从 `$_SERVER['QUERY_STRING']` 取请求串，剥离 `&` 后续参数与 `.html` 后缀，按 `/` 切分为 `module / action / params`：

```
QUERY_STRING: content/list/2-5
  → module = content
  → action = list
  → getParam(2, 0) = 2   （"-"切分的第 0 段）
  → getParam(2, 1) = 5   （"-"切分的第 1 段）
```

- **默认模块回退（第一级）**：URL 无模块段（如访问站点根 `/`）时，读站点配置 `site_defaultmodule` 作为默认模块（模块管理界面可"设为默认"，默认模块禁用时被拒绝）；未设置或未安装时回退 system（`system/start` 匿名显示引导页，已登录进入桌面）。
- **短 URL 回退（第二级）**：首段不是已安装模块名（`system.modules` 配置中不存在）时，首段被重新解释为**默认模块**的 action，即默认模块的 action 可省略模块名直接访问：默认模块为 content 时 `/read/5` 等价于 `/content/read/5`。若该 action 在页面入口中不存在，落入 `404` 分支输出 404 模板。

**URL 形态**：由 `site_rewrite` 配置决定前缀，`/module/action`（开）或 `/?module/action`（关），模板中统一用 `$R->getPageUrl()` / `$R->getCtrlUrl()` 生成链接，不手写 URL。

**分发次序**：

1. include `module/<m>/index.php`，输出进入缓冲（路由只分发到模块，不做任何模块特判；主题分发是 content 模块内部行为——主题存在 `dispatcher.php` 时由模块入口先交给主题处理）；
2. 输出可写入 `store/cache/output/` 文件缓存（按 `site_cachetime` 失效）；
3. 404 由 `print404()` 兜底，二次 404 直接终止。

### 4.3 数据库（`$D`，cls.database.php）

- 单驱动 MySQL（PDO），连接参数来自 `store/config/system.database.php`；缺少该配置时引导至安装向导。
- 表名参数只写裸表名（如 `group`），驱动补 `DB_PFIX` 前缀（`fc_group`），模块代码不感知前缀；仅 SQL 片段（`exec()`/`where()`）中的表名需要用 `T[group]` 占位。
- 读取门面 `DB::table('表名')`：返回查询构造器，是业务代码唯一的读取入口；门面与驱动同文件，由 `startup.php` 预加载（只 include，不建立连接）。
- 写方法：`insert()` / `update()` / `delete()` / `exec()`（含 DDL），均接受数组型字段值；`lastId()` 取自增 ID，`raw()` 声明常量表达式，`transaction($callback)` 以闭包执行事务、异常自动回滚。
- 读取出口（查询构造器）：`row()` / `rows()` / `value()` / `column()` / `count()` / `exists()`。

### 4.4 模板（`$T`，cls.template.php）

- 变量绑定 + PHP 原生模板，无独立模板语法。
- 后台界面与模块页面分别使用 `system` 与各模块 `template/` 目录下的模板，统一入口 `$T->show()`。
- 前台主题模板（module/content/themes/）属 content 模块的展示定制能力，不属于内核；渲染入口是 content 类的 `display($file)`：模板根指向主题目录（`PATH_THEME`，常量随 cls.content.php 加载），并以 bind 注入内容对象 `$C`，模板内照常使用 `$C->getNavigate()` 等。内核模板类不含该方法——内核不含业务的典型实现。

### 4.5 鉴权（`$U`，cls.member.php）

- 当前用户状态、登录 / 注销、皮肤。
- `checkRights('模块.实体.动词')`：动作接口的统一权限检查点，无权限即终止。
- 登录失败限流由 member 模块的 `cls.loginlimit.php` 承担（静态方法 `locked() / fail() / clear()`），计数落 `store/cache/login/`，不新增数据表；取 IP 走 `$A->getUserIP()`。

### 4.6 皮肤体系

- 皮肤目录：`module/system/skins/<name>/`，每个皮肤含 `style.css` 与 `skin.php` 描述；`listSkins()` 枚举可用皮肤。
- 取皮肤走 `getSkin()`，四级回落，每一级都先过 `^[a-z0-9_-]+$` 白名单并校验目录存在：

```
登录用户 us_skin（session） → 公共记忆 Cookie（skin，30 天） → system.settings 的 skin_default → 内核兜底 default
```

- 写入时机：登录成功加载用户皮肤时、后台手动切换时；退出登录不清除该 Cookie，登录页据此记住上次皮肤。
- 旧的系统级皮肤配置已移除，皮肤不再对全站生效，而是跟随用户。
- 皮肤相关常量（`startup.php` 定义，模块与模板直接用）：
  - `URL_SKIN`：当前皮肤目录 URL，形如 `/module/system/skins/dark/`；
  - `SKIN_NAME`：当前皮肤名（`basename` 取值），用于匹配第三方控件的同名皮肤；
  - `DATE_SKIN`：日期控件实际使用的皮肤名，等于 `SKIN_NAME`，但**仅当** `tools/datepicker/skin/<SKIN_NAME>/` 存在，否则回落 `default`。
- 第三方控件的皮肤联动：My97DatePicker 与 Quill 都是自带配色的独立组件，皮肤 CSS 变量进不去（datepicker 更是渲染在独立子文档）。因此
  - 日期控件按目录提供多套皮肤，调用点统一写 `WdatePicker({skin:'<?php echo DATE_SKIN; ?>'})`，新增皮肤时同步复制一份 `tools/datepicker/skin/<新皮肤名>/datepicker.css`（缺目录自动回落，不会报错但会显示浅色）；
  - Quill 由 `tools/quill/fc.quill.css` 适配，该文件加载在 `quill.snow.css` 之后且使用设计令牌，新增皮肤无需额外处理。

### 4.7 附件与上传下载

- 上传：`fileupload` 类按 `system.settings` 的 `uploadSize` 与 `uploadSuffix`（image / file / archive / video / audio 五组）校验；图片判定 `isImage()` 同样读配置，不硬编码。
- 物理路径：`store/<uploadDir>/<模块目录>/<年月>/<日>/<随机名>.<后缀>`；附件记录入 `fc_attached`，含 32 位随机 `at_token`（唯一键）。
- 下载：页面入口 `system/file/<token>`，token 不可枚举；远程附件 302 跳转；本地附件支持单段 Range（`bytes=a-b`、`bytes=-N`），206 分块输出，无 Range 或畸形 Range 回退 200 整文件，64KB 流式读取不占内存。
- 删除：数据库记录与物理文件在同一事务内处理，删除后自底向上 `rmdir` 空目录链，带上界保护（不越出上传根、不删根本身）；非空目录 rmdir 失败即停止，并发安全。

### 4.8 配置文件归属

| 文件 | 性质 | 内容 |
|---|---|---|
| `system.database.php` | 安装生成，不入库 | 数据库连接，仓库仅提供 sample |
| `system.settings.php` | 手工配置 | 上传限额与后缀、Cookie 参数、system_user、skin_default、uploadDir |
| `system.site.php` | 自动化 | 站点信息、开关、默认模块（后台保存动作写入） |
| `system.modules.php` | 自动化 | 模块注册表与菜单缓存（模块管理安装/更新时生成，禁止手改） |
| `content.settings.php` / `message.settings.php` | 自动化 | 模块自己的开关与参数 |

## 五、模块系统

### 5.1 目录约定

```
module/<模块名>/
├── module.php     声明类 FCModule<Name>（目录名首字母大写）
├── index.php      页面入口（处理请求并渲染页面）
├── control/       动作接口（只处理请求，不渲染页面）
├── library/       模块类库（cls.<名称>.php）
├── template/      模块模板
├── scripts/       模块私有静态资源（可选，自备 js/css）
├── icons/         模块图标（桌面与菜单引用，如 module.png）
└── install.mysql.sql   建表脚本（安装时自动执行，可缺省）
```

静态资源分层（内核提供公共设施，模块自备私有资源）：

| 类别 | 位置 | 取址常量 | 说明 |
|------|------|---------|------|
| 内核公共脚本 | `module/system/scripts/` | `URL_SCRIPTS` | jQuery、lib.system.js 等，所有模块可直接引用 |
| 内核公共组件 | `module/system/tools/` | `URL_TOOLS` | quill（富文本编辑器）、datepicker（日期选择）、excolor（颜色选择）、phpmailer（邮件发送） |
| 后台皮肤 | `module/system/skins/` | `URL_SKIN` | 后台界面样式，各模块默认使用以保证风格统一 |
| 模块私有资源 | `module/<模块名>/scripts/`、`icons/` | `URL_MODULES.'<模块名>/...'` | 模块自有的 js / css / 图标 |

注意：`URL_SCRIPTS` / `URL_TOOLS` 恒指向内核公共区，**不是"当前模块的脚本目录"**；模块私有的文件放在自身 `scripts/` 下并自行拼取 URL。

静态资源引用统一追加 `?v=<?php echo ASSET_VERSION; ?>`：`ASSET_VERSION` 由 `startup.php` 取皮肤 `style.css` 与 `lib.system.js` 的最新修改时间生成，改样式或脚本后无需用户强制刷新。

### 5.2 声明类 module.php

```php
final class FCModuleDemo
{
	public $basic = array
	(
		'for'     => '1.0.5+',        // 兼容的内核版本
		'name'    => '演示模块',       // 后台显示名（桌面图标标题）
		'icon'    => 'module.png',
		'desc'    => '模块说明。',
		'version' => '1.0',
	);

	public $rights = array
	(
		'demo.thing.select' => '查看',
		'demo.thing.insert' => '添加',
		'demo.thing.update' => '编辑',
		'demo.thing.delete' => '删除',
	);

	public $menus = array
	(
		//单组模块：组名与模块名一致 不配组图标（回落模块图标）
		'演示模块' => array
		(
			'items' => array
			(
				'查看事物' => array('url'=>'fc.thing.select', 'icon'=>'thing.png', 'rights'=>'demo.thing.select'),
			)
		),
	);

	public function install()   { /* 建表、初始化 */ }
	public function uninstall() { /* 清理 */ }
}
```

命名约定（全系统统一，AI 协作的关键约定）：

| 对象 | 约定 | 示例 |
|------|------|------|
| 模块目录名 | 小写单词 | `demo` |
| 声明类名 | `FCModule` + 目录名首字母大写 | `FCModuleDemo` |
| 权限名 | `模块.实体.动词` | `demo.thing.insert` |
| 后台动作 mode | `fc.实体.动词`（前端动作无此前缀） | `fc.thing.insert` |
| 模块类库 | `cls.模块名.php` | `cls.demo.php` |

### 5.3 入口文件：index.php 与 control/index.php

模块有两个请求入口，内部结构相同（switch 分支 + 前后端注释分隔），职责不同：

| 入口 | 分发依据 | 职责 | 引导方式 |
|------|---------|------|---------|
| `index.php` | `$R->action` | 处理请求**并渲染页面** | 由路由 include，顶部以 `SYSTEM_INCLUDE` 守卫 |
| `control/index.php` | `?mode=` 参数 | 只处理请求（数据读写），**不渲染页面** | 独立 HTTP 入口，自行 `include '../../startup.php'` |

两个入口的 case 都分两类，以固定注释分隔、固定顺序放置：

- `////前端请求////` 段：**不以 `fc.` 开头**的 case，服务于前台页面（访客侧），如留言提交、评论加载；
- `////后端请求////` 段：**以 `fc.` 开头**的 case，服务于后台管理界面，必须以 `checkRights` 作为第一个语句。

页面入口骨架（index.php）：

```php
<?php
if (!defined('SYSTEM_INCLUDE')) exit('Access Denied.');

switch ($R->action)
{
	////前端请求////
	case 'list':
		$R->cacheopen = TRUE;
		$C = FCApplication::loadLibrary('content');  // 需要主题渲染时加载
		$T->bind('items', $items);
		$C->display('list');
		break;

	////后端请求////
	case 'fc.thing.select':
		$U->checkRights('demo.thing.select');
		$T->show('thing.list');
		break;
}
```

动作接口骨架（control/index.php）：

```php
<?php
include '../../startup.php';

switch ($mode = $A->strGet('mode'))
{
	////前端请求////

	////后端请求////
	case 'fc.thing.insert':
		$U->checkRights('demo.thing.insert', TRUE);

		$name = trim($A->strPost('name'));
		if ($name == '')
		{
			echo 'ERR|请输入名称。|name';
		}
		else
		{
			$D->insert('thing', array('name' => $name, 'time' => time()));
			$A->logInsert('添加了事物');
			echo 'YES';
		}
		break;
}
```

返回值约定：`YES` 表示成功；`ERR|消息` 表示失败；`ERR|消息|字段名` 表示失败且前端聚焦该字段。

### 5.4 模块生命周期

```
安装    校验声明 → 写入模块注册信息（权限/菜单）→ 运行 install()（模块内调用 $A->installTables() 执行 install.mysql.sql，IF NOT EXISTS 已存在的表跳过，卸载重装不丢数据）→ 菜单/图标上桌面
禁用    菜单/图标下桌面，路由不再分发到该模块，代码不执行
卸载    运行 uninstall() → 移除权限与菜单 → 删除模块记录
```

安装时校验规则：`$menus` 引用的每项 `rights` 必须存在于本模块 `$rights` 声明中，不通过则拒绝安装并提示具体菜单。该校验只能保证引用**合法**（防拼写错误、防跨模块误引），保证不了引用**正确**——菜单指到另一个合法权限属于语义错位，仍需人工复核。

## 六、权限体系

```
模块 $rights ──安装注册──▶ 内核权限表
                              │
用户组（gr_rights 持有）◀──────┤
                              │
后台菜单显隐（$menus.rights）──┤
动作入口校验（checkRights）────┘
```

- 权限只到**操作级**，不做数据行级权限，这是有意的设计边界。
- 动词词表以 `select / insert / update / delete / order` 为基础，允许按需扩展（如 `upload`、`disable`），扩展动词必须在权限名中保持全系统一致。
- 菜单隐藏只是体验优化，安全边界在动作入口的 `checkRights`。

## 七、后台桌面（WebOS）

- 桌面是模块注册表的可视化：模块图标随安装 / 禁用 / 卸载自动增减，桌面状态即系统状态。
- 分层解耦原则：

```
窗口系统层    桌面、窗口管理、任务栏（system 提供）
通用部件层    表单、表格、上传、翻页等控件（与窗口层无关）
业务模块层    只使用通用部件组装功能，不感知窗口实现
```

- 移动端退化策略：小屏幕下窗口自动最大化单视图，不提供自由拖拽。具体规则：

| 断点 | 判定依据 | 作用范围 |
|------|----------|----------|
| `max-width:800px` | 窗口宽度 | 后台布局：任务栏窗口卡片横向滚动、窗口打开即最大化、外框 4px |
| `max-width:500px` | iframe 自身宽度 | 内容页：表单单列、搜索栏与工具栏换行、列表表格在滚动容器内横向滚动（首列 sticky）、按钮触控高度 34px；`table_tools` 折行行距 8px、工具条与列表间距 10px |
| `hover:none` / `pointer:coarse` | 输入设备能力 | 触屏交互：禁用窗口拖拽、模块管理不初始化拖拽排序 |

- `500px` 断点同时覆盖非表格页：模块管理（卡片高度自适应、操作区独立成行）、缓存管理（右侧操作区 160px、更新周期标签独立成行）、皮肤设置（缩略图 96×60、信息列 116px）、已上传文件（搜索独占一行）。皮肤设置窗口宽度固定 520，刻意大于断点，保证桌面端保持原布局。

- 布局看宽度、交互看能力，两轴独立判定：宽屏平板同时具备触摸能力时也能正确降级。
- 移动端不维护独立菜单组件，直接复用桌面端的左侧模块竖栏与网格菜单；窗口框架样式在移动断点内保留独立副本，移动端专属调整只改该副本。
- 窗口几何：功能窗口创建时即按最大化尺寸生成（`$(window).height()-13-30`）并预置最大化缓存，最大化按钮不改变尺寸；显式指定宽高的小窗（登录、找回密码）使用两端独立常量，桌面 550×240、移动端 340×380。
